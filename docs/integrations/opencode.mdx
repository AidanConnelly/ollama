[OpenCode](https://opencode.ai) is an open-source coding agent that runs in your terminal, reads your project, edits files, and runs commands.

Ollama configures OpenCode to use local and cloud models.

## Get started

Launch OpenCode with Ollama:

```shell
ollama launch opencode
```

## Manual setup

<p className="manual-step-title">1. Install OpenCode</p>

<CodeGroup>

```shell macOS / Linux
curl -fsSL https://opencode.ai/install | bash
```

```powershell Windows
npm install -g opencode-ai
```

</CodeGroup>

<p className="manual-step-title">2. Configure Ollama as a provider</p>

Add an Ollama provider to `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama",
      "options": {
        "baseURL": "http://localhost:11434/v1"
      },
      "models": {
        "qwen3.5": {
          "name": "qwen3.5"
        }
      }
    }
  }
}
```

<p className="manual-step-title">3. Run OpenCode</p>

```shell
opencode
```

To configure OpenCode with Ollama without starting an interactive session:

```shell
ollama launch opencode --config
```

### Configuration precedence

`ollama launch opencode` starts OpenCode with an inline config for the selected Ollama model. It does not overwrite `~/.config/opencode/opencode.json`; existing OpenCode settings still apply.

Models defined only in `opencode.json` do not appear in the `ollama launch` model picker.

See OpenCode's [config precedence](https://opencode.ai/docs/config/#precedence-order).

## Experimental edit constraints

Set `OLLAMA_OPENCODE_EDIT_CONSTRAINTS=1` before starting Ollama to enable the native `oldString` sampling mask. This requires a rebuilt llama.cpp payload advertising `oldString-mask-v1`. Older payloads and unsupported tool-call formats return an explicit configuration error.

Messages, tool definitions, rendered prompts, and prompt tokens are unchanged. Only the contents of `oldString` in actual `edit` calls are masked, before top-k/top-p sampling. Paths, replacement text, tool selection, and argument order remain free. Matches may be repeated, whitespace, partial words, or arbitrary multiline substrings.

The request's OpenCode working directory determines the eligible files. Git must be installed; nested `.gitignore` rules work even without a Git repository. Git metadata, directories, binary files, and symlinks outside the root are excluded. The runner reads and indexes a selected file on demand, up to 16 MiB. When `oldString` comes first, it uses separate indexes for all eligible files, with a 128 MiB total contents budget. Exceeding that budget disables masking rather than using a truncated subset. A later valid path narrows the match; an incompatible late path or an ineligible target produces an explicit unmasked fallback. Snapshots and eligibility refresh on the next request.

Local logs and inference telemetry report activation, fallback reasons, index sizes, and masked-token counts. Mask telemetry never includes file contents. For paired experiments, also set `OLLAMA_OPENCODE_EDIT_EXPERIMENT=1` in **both** conditions to disable speculative and backend sampling consistently. An unmasked fallback is not evidence that masking worked.
